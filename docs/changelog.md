## 0.18.55 - 2026-05-23 03:27

- ウィンドウが前面に戻ったあとも非アクティブ扱いのままになり、バックグラウンド用の 50ms sleep に入り続けて FPS が 18〜25 付近まで落ちることがある問題を修正しました。アクティブ/最小化状態の更新を ImGui の Win32 ハンドラより前で処理し、メインループ側でも前面ウィンドウ状態を確認するようにしました。
- Debug タブに `Frame Timing` を追加し、フレーム時間、メッセージ処理、ImGui 新規フレーム、メインスレッド評価処理、UI 描画、ビューポートタブ、ノードエディタ、インスペクタ、`RenderFrame`、`Present`、FPS 制限 sleep、バックグラウンド sleep、fence 待ち、ウィンドウ状態を確認できるようにしました。
- `FPS Limit` の sleep 計算を、前回の予定時刻を積み上げる方式から現在フレームの開始時刻基準へ変更しました。60 FPS 制限時に 1 フレーム分を超えて余分に sleep し、実 FPS が大きく落ちることがある問題を防ぎます。
- ビューポート左上メニューの `Mesh` がオフのときは、グリッド表示がオンでも 3D オフスクリーンプレビューを更新しないようにしました。メッシュ非表示時にグリッドや天球/雲の更新だけで GPU プレビューと fence 待ちが残る状態を避けます。
- 2D ビューの ImGui 矩形描画を最大 256 x 256 サンプルに抑えました。高解像度地形で最大 1024 x 1024 個の矩形を毎フレーム追加して `DrawUi` が重くなる問題を軽減します。
- ノードエディタ背景のドット描画を軽量化しました。小さな円ではなく矩形点で描き、ズームアウト時は画面上の密度が高くなりすぎないよう間隔を広げます。
- `FPS Limit` の待機で Windows の粗い sleep による寝過ぎが起きにくいよう、長い残り時間だけ 1ms sleep し、終端は `yield` で待つ方式にしました。
- ビューポート右上の FPS 表示を ImGui の平均 FPS ではなく、Debug タブの `Frame` と同じ直近フレーム実測値から計算するようにしました。

## 0.18.54 - 2026-05-22 11:15

- AO の半径指定が実際のメートル距離として効くようにしました。従来は最大 24 テクセル分までしか参照していなかったため、大きな `AO 半径 (m)` でも谷や盆地スケールに届きにくい状態でした。
- AO のサンプル距離を近距離が密な二乗分布に変更し、細部のくぼみを残しながら指定半径まで遮蔽を調べるようにしました。
- `docs/display/ambient_occlusion.md` を追加し、AO の目的、現在の方式、パラメータ、注意点を記録しました。

- AO に「AO 半径 (m)」スライダーを追加しました。10〜5000 m の範囲で遮蔽サンプルの最大距離を設定でき、小さい値では岩の窪みなど細部のみ、大きい値では谷・盆地スケールまで暗くなります。変更時は AO テクスチャを自動再計算します。
- ハイトフィールドベースのホライゾン AO を追加しました。8 方向 × 24 サンプルの地平線仰角から天空可視率を計算し、谷や凹部のアンビエントライトを遮蔽します。表示パネルの「アンビエントオクルージョン」セクションにある「AO」チェックボックスでオン / オフを切り替えられます。AO 強度スライダーで暗化の強さを 0–1 で調整できます。ハイトフィールドが変わると GPU コンピュートシェーダーで自動再計算されます。

- README を現在のプロトタイプ内容に合わせて更新し、`Terrain Size (m)`、主要ノード、GPU backend、表示機能、関連ドキュメントへの案内を整理しました。
- 予定タスクに、スプラインパスのネットワークから山脈や尾根の土台になる `Heightmap` と `Mask` を作る `Spline` ノードを追加しました。
- `docs/plan/terrain_workflow.md` を追加し、岩、土、植生、砂礫を分けて考える地形制作の基礎フローを整理しました。

## 0.18.49 - 2026-05-22 07:05

- Rock の多面体周辺に出ていた **「ハロー(柔らかな円形ドームの漏れ)」を解消** しました(3.9.1)。

  - 新式: `edgeSharpness > 0` のとき多角形 SDF で **ハードクリップ**(多角形外は `continue`、この岩の寄与なし)。`edgeSharpness` の値は **クリップ内部の高さ形状** を radial / polyhedral でブレンドする役割に変更。シルエットは常に多角形のクリーンな縁になります。
  - 既定値を `Edge Sharpness 0.7 → 1.0` に変更。新規ノード配置で完全に平らなダイヤモンドカット多面体が出ます。柔らかい円形ドームに戻したいときは 0 に。
- Rock ノードのシルエットを **多角形 SDF ベースに刷新**、ダイヤモンドカット風の角張った岩を作れるようにしました(3.9.0)。
  - 新規パラメータ `Edge Sharpness (%)`(既定 70%)を追加。0 で従来の円形ドーム、1 で 4–7 角形のダイヤモンドカット多面体シルエット。中間値で連続ブレンド。
  - 岩ごとに辺数(4–7)、各辺の法線角度ジッタ(`±π/N × 0.5`)、各辺の半径ジッタ(0–30% 内側)が個別ハッシュで決まり、岩同士でまったく同じ多角形にならないように。
  - 多面体成分は SDF の内部距離を `baseInradius` (`domeRadius_per × cos(π/N)`) で正規化。`Edge Sharpness = 1` では `pow` 指数も自動的に 1.0 に落ちて、平らな三角形ファセットがそのまま立つように(`Facet Sharpness` の頂点先鋭化は円形ドーム時のみ効く)。
  - 既定値を `Edge Sharpness 0.7` にしたので、新規ノード配置で「ぼけた円」ではなく既に多面体寄りのシルエットが出ます。完全な円形ドームに戻したい場合は 0 に。
  - コスト: 多面体 SDF 計算は内側ループで 4–7 辺 × ~7 ops。`Edge Sharpness = 0` ではスキップされるので旧コストと同等、最大設定で 1 ピクセルあたり ~50 ops 増(1024² 全体で +100ms 程度)。
- Rock ノードのサイズ入力を **メートル単位に変更**、Voronoi 由来の Crack 機能を削除しました(3.8.0)。
  - `Rock Size Min/Max`(ratio: ドーム半径 ÷ (Density / 2))を `Rock Size Min (m)` / `Rock Size Max (m)` に変更。岩の直径を直接 m 値で指定できるようになり、Density(scatter 間隔)とは独立して入力できます。デフォルト `5.0m / 10.0m`。
  - `Crack Depth (m)` を削除しました。サイズが scatter ピッチに連動しなくなった結果、Voronoi セル境界が「岩の境界」と一致しなくなり、亀裂彫り込みの位置が物理的に意味を持たなくなったため。max 合成で重なる岩同士の接合線には自然な折れ線が出るので、明示的な彫り込みは不要です。
  - アルゴリズム内部では引き続きセル単位で距離計算(`rockSizeCells = rockSizeM / density`)。F1/F2 追跡も削除され、走査ループがシンプル化(crack を使っていなかった分のコストが落ちる)。
  - プロジェクト互換: 過去のキーはすべて自動マイグレーション。`rockFill` (3.5.x) / `rockSize` (3.6.0) → `Min = Max = ratio × density` で m 換算。`rockSizeMin/Max` (3.7.0) → 各 `× density` で m に。新規保存は `rockSizeMinM` / `rockSizeMaxM` キー。
  - Voronoi の使い方: 「Voronoi」は **scatter 生成器(擬 Poisson 分布)としての役割のみ** に整理しました。決定的・低コストで岩中心を均等にばらまける利点はそのまま、サイズ・形状の制御は完全に独立。
- Rock ノードに **岩ごとのサイズレンジ・回転・アスペクト比** を追加し、GeoGen の Rock のような散らばり感を出せるようにしました(3.7.0)。
  - `Rock Size`(単一値)を `Rock Size Min` / `Rock Size Max` に分割。各岩は `[Min, Max]` の範囲からハッシュで個別にサイズを選びます。
  - `Rotation Variation (%)`(既定 1.0): 各岩にランダムな 2D 回転(0..2π × variation)を与えます。表面のファセット場が回転するので、隣り合う岩の面の向きがバラバラになり「同じパターンの繰り返し」感が消えます。
  - `Aspect Variation (%)`(既定 0.3): 各岩の細長さ(楕円アスペクト比)を変化させます。`pow(2, aspectVar × hash)` の対称な乗法レンジで面積保存し、回転と組み合わせて様々な向きの細長い岩が混ざります。最大設定で 2:1。
  - 表面ファセット場を **ピクセル共有** から **岩ローカル(回転・アスペクト座標系)** に変更。岩ごとに固有のオフセットも乗るので、岩の向きに沿って面が並び、隣り合う岩で同じ面が見えません。重なる岩の境界にはシルエットの折れ線が立ち、離散的な岩塊として見えます。
  - `searchRadius` を `rockSizeMax × pow(2, aspectVar)` に連動させて自動拡張(既定で 3×3、最大設定で 7×7)。`crackVisibility` も `avgRockSize` ベースに変更。
  - 既定値を `rockSizeMin = 0.7 / rockSizeMax = 1.2 / rotationVariation = 1.0 / aspectVariation = 0.3 / facetSharpness = 0.5` に調整し、新規ノード配置で散らばった多面体岩塊が出るように。
  - プロジェクト互換: 旧 `rockFill` / `rockSize` キーは自動的に `rockSizeMin = rockSizeMax = 旧値` として読み込まれます(=固定サイズ動作の再現)。新規保存は `rockSizeMin` / `rockSizeMax` キーになります。
- Rock ノードを書き換え、**岩のサイズと密集度を独立に制御** できるようにしました(3.6.0)。
  - 旧 `Rock Fill (%)`(0.05〜1.0、セル内に収まる比率)を `Rock Size`(0.05〜3.0)にリネームし、上限を拡張。`Rock Size > 1.0` で岩のドームが隣接セルにはみ出して **重なる** ようになり、「Density は小さい(=岩がたくさん) + Rock Size は大きい(=岩が大きい)」という従来できなかった組み合わせ(大きい岩を密集)が表現可能に。
  - アルゴリズムを「1 セル = 1 岩」から **近傍セル走査 + 寄与の最大値** に変更。各ピクセルで近傍セル(`Rock Size` に応じて 3×3〜5×5 を自動選択)を走査し、最も高いドーム寄与を採用します。`Rock Size ≤ 1.0` のときは従来と同じ 3×3 走査でほぼ同コスト、`Rock Size = 3.0` で約 2.8 倍。
  - 表面ディテールに **多面体モード** を追加: `Facet Sharpness` (0..1) で「滑らかなドーム + 丸い凹凸」から「平らな面 + 鋭いエッジ」に連続的に切り替えられます。`Facet Scale` (0.5..8.0) で 1 つの岩に乗る面の細かさを調整。サブセル Voronoi の F1/F2 でフラットな面と境界クレースを作るので、結晶質クリスタル風から大きな割れ岩まで幅広く作れます。
  - ドーム自体の落ち方も `Facet Sharpness` 連動で `pow((1 - d/r), 1 + facetSharpness × 1.5)` に変更し、多面体寄りで頂点が尖るように。
  - 重なり領域では Voronoi セル境界の亀裂(`Crack Depth`)が物理的に意味を失うので、`Rock Size > 1.0` で自動的にフェードアウトする `crackVisibility` を導入。
  - 表面モジュレーションは「ピクセル単位」で評価するため、重なる岩同士の表面が継ぎ目なく繋がります(岩ごとに別の凹凸が走って境界が見える、ということが起きない)。
  - プロジェクト互換: 旧 `.terrainproj` の `rockFill` キーは自動的に `rockSize` として読み込まれます。新規保存は `rockSize` キーになります。
- Phase 2c の crash 切り分け第二段(2c-2): **GPU モードでもシャドウが描画される** ように `g_meshPreviewDisplacementShadowPso` を再導入しました。前回(reverted した 2c)からの変更点は **シャドウ描画中にバインドする root param 3 (shadowMap SRV) をシャドウターゲット自身ではなく cloud の dummy SRV に差し替え** たこと。シャドウパス中はシャドウターゲットが `D3D12_RESOURCE_STATE_DEPTH_WRITE` でバインドされており、その同じリソースの SRV を bind すると D3D12 が DSV/SRV alias として detect → device removed していた可能性が高いです(displacement shadow PSO は PS を持たないので t0 は実際には参照されないため、dummy で問題なし)。
- Phase 2c の crash 切り分けの第一段(2c-1): **CPU メッシュアップロードのスキップだけを再導入** しました。`GpuDisplacement` モードでは `UpdateMeshPreviewBuffers` を呼ばず、~40MB の VB/IB アップロードを完全削減します。`displacementReady` を early-return 条件に追加して、CPU 頂点バッファが無くても displacement 経路だけで描画継続できるように。シャドウのディスプレイス経路化(これが落ちていた可能性が高い)はまだ入れず、GPU モードではシャドウが描画されない既知の制限となります — 2c-2 でシャドウ経路を再追加し原因を切り分けます。
- GPU メッシュバックエンドに切り替えるとアプリがクラッシュする不具合を一時的に回避するため、Phase 2c で入れた「CPU メッシュアップロードのスキップ」と「シャドウのディスプレイス経路化」を **revert** しました。GPU モードでは現状ハイブリッド動作(CPU メッシュは引き続きアップロード + サーフェス描画のみディスプレイス)で、純粋な性能向上にはなっていませんが落ちないことを優先しました。クラッシュの原因切り分けと再実装は次の対応で行います。
- GPU 頂点ディスプレイスの **本来の高速化**(Phase 2c):
  - GPU モードでは CPU メッシュの GPU バッファアップロード(頂点 / 三角形 / エッジ)を **完全にスキップ**。`UpdateMeshPreviewBuffers` を呼ばないので、約 40MB の VRAM アップロードが不要になります。CPU 側でのメッシュ生成自体は 2D プレビュー用に継続(skipは将来検討)。
  - シャドウ描画も displacement 経路に移行 (`g_meshPreviewDisplacementShadowPso` + 静的 IB を使用)。シャドウ VS がハイトテクスチャを直接サンプリングして光空間に投影するので、CPU メッシュ無しでも terrain self-shadow が描画されます。
  - 早期リターン条件を更新: hasMeshVertices(CPU 経路)または displacementReady(GPU 経路)のいずれかがあれば描画を継続。
  - 既知の制限: GPU モードではワイヤフレーム描画はスキップ(displacement wire PSO 未実装。CPU モードに切り替えれば従来通り表示可能)。グリッドは独立バッファなので両モードで動作。
  - 体感: 1024² で従来 ~70ms → ~10ms 想定(CPU メッシュ生成 ~30ms + テクスチャアップロード ~6ms — VRAM アップロード分を完全削減)。
- GPU 頂点ディスプレイスをサーフェス描画に **接続**(Phase 2b)。`表示設定 → Mesh Backend` で `CPU Mesh` ↔ `GPU Displacement` を切り替えられます。GPU モードでは:
  - 評価ごとにハイトフィールド + マスクが `R32_FLOAT` テクスチャへ `CopyTextureRegion` でアップロード(`UploadDisplacementHeightfield`、~3 ms / 1024²)。
  - サーフェス描画は新しい `g_meshPreviewDisplacementSurfacePso` + 静的グリッド IB で、頂点シェーダーがハイトテクスチャから Y を引いて配置 + 4-tap 法線。
  - シャドウ描画・ワイヤフレーム・グリッドは引き続き CPU メッシュ経路を使用(本コミットでは CPU メッシュアップロードはスキップしていません — 純粋な追加経路で、まだ最適化前)。
  - dirty チェックに `meshBackend` を追加してトグル変更時に再評価を発火。
  - 既知の制限: シャドウとサーフェスでメッシュ細分が一致しないと細かい段差で自己シャドウが少し外れて見える場合あり。Phase 2c で CPU メッシュアップロードのスキップ + シャドウもディスプレイス経路に切り替える予定。

- ハイトフィールド→メッシュ生成 (`BuildMeshFromHeightfield`) をフル並列化し、パラメータ操作中のメッシュ再生成負荷を削減しました(Phase 1)。具体的な変更点:

- 薄い雲が背景の空より暗く見えていた問題を修正しました。雲シェーダーは `accumulated += lit * dA` でレイマーチを積分していて、これは既に alpha 乗算済み (premultiplied) の色を出します。にもかかわらずブレンド状態が `SRC_ALPHA / INV_SRC_ALPHA` で 2 度目の alpha 乗算をしていたため、たとえば alpha = 0.2 の薄い雲では `0.2 × 0.2 + 0.8 × sky = 0.04 + 0.8 × sky` となって空より暗くなっていました。`ONE / INV_SRC_ALPHA` (premultiplied) に変更して `accumulated + (1 - alpha) × sky` で正しく合成するようにしました。
- 雲のテクスチャに縦/横の継ぎ目が見えていた問題を修正しました (特にフィールド中央 = 地形中心で目立っていました)。`cloud_density.hlsl` の Perlin 生成を周期版 `Perlin3DPeriodic` / `Fbm3DPeriodic` に置き換え、整数座標を `mod period` してから勾配ハッシュを引くようにしました。`Fbm3D` の各オクターブでも周波数倍と同じく period も倍にすることで、`uvw = 0` と `uvw = 1` で勾配配置が一致してテクスチャがシームレスにタイリングします。`SamplerState` の WRAP モードと組み合わさってフィールド内のどこでも継ぎ目が出なくなります。
- 雲が地平線まで無限に続いてしまう問題を修正しました。`CloudSettings` に `fieldRadius` と `fieldFalloff` を追加し、地形の中心 (mesh bounds の中心) を原点に円形のフィールド境界を設けて、その外側では雲の密度を 0 にフェードアウトします。シェーダー (cloud_render / cloud_shadow) の `SampleCloudDensity` で `ComputeFieldFade` を乗算する形。デフォルトは半径 6000m / フェード 2000m なので、典型的な 4-8km 地形だと地形の周りだけに雲が出る形になります。表示設定パネルに「Field Radius」「Field Falloff」を追加し、`.terrainproj` にも保存します。
- レビューフィードバックの反映: (1) 表示設定パネルの `Lighting Mode` から `Shadow Debug` を削除しました。シェーダー側の `DebugShadowColor` 分岐も死コードになるので除去。`.terrainproj` 経由で値 2 が入っていた古いプロジェクトは load 時に 0..1 にクランプされます。 (2) 表示設定パネルの「天球」「ボリューム雲」の前に `ImGui::SeparatorText` を入れて区切りを入れました。雲セクション側のトグルラベルも「ボリューム雲」→「有効」に短縮。 (3) 雲の色が灰色っぽく見えていた問題を直しました。`cloud_render.hlsl` のシェーディングが太陽の高度と垂直プロファイルで二重に減衰させていたため、白を指定しても 50% 程度のグレーに収束していました。シンプルに `cloudColor × lerp(0.85, 1.05, yNorm)` の top-lit ランプだけにして、上面でフルカラー、下面で 85% に落ち着く形に。
- 雲が地形に影を落とすようになりました (Phase 3)。compute shader [shaders/cloud_shadow.hlsl](shaders/cloud_shadow.hlsl) で、地形フットプリント上空に置いた 1024² R8_UNORM の top-down ビューから太陽方向にレイマーチして雲帯の透過率を 2D テクスチャに焼きます。これを mesh shader でサンプルし、地形頂点 (x, z, y) を太陽方向に altitudeMin まで投影した位置で透過率を読んで sun + ambient に乗算します。CloudSettings に Shadow Strength / Resolution / Samples を追加し、UI と `.terrainproj` に保存します。雲影テクスチャは毎フレーム再生成 (Sun direction や Wind offset の変化に追従)、約 0.5ms / 1024². mesh root signature に b1 の root CBV (CloudShadowMeshConstants) と t1 のテクスチャテーブルを追加 (合計 64 DWORD ぴったり)。雲が無効化されたときは 1×1 の白テクスチャをバインドしてシェーダー側でゼロ強度として扱います。
