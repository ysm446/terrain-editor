# KTT Fluvial Erosion アルゴリズム入門

このメモは、KTT の `Fluvial Erosion` ノードが何をしているのかを、実装の細部へ入る前に段階的に理解するための読み物です。
正確なパラメータ名や OpenCL カーネルの詳しい対応は `fluvial_erosion_hda_notes.md` にまとめています。

## まず何をするノードか

`Fluvial Erosion` は、山そのものをゼロから生成するノードではありません。
入力されたハイトフィールドに対して、水が流れたような谷、細い水路、削られた場所、堆積した場所を追加するノードです。

大まかには、次のような考え方です。

1. 地形の傾きから、水が流れそうな方向を調べる。
2. 地形上にたくさんの小さな粒子をばらまく。
3. 粒子を流れ方向へ少しずつ動かす。
4. 粒子が通った場所を削る。
5. 削った土砂を別の場所へ少し戻す。
6. これを何度も繰り返して、流路らしい筋を育てる。

## 全体の流れ

KTT の処理は、だいたい次の順番で進みます。

1. 入力ハイトフィールドを受け取る。
2. 必要なら細かいノイズを少しならして、流れやすい地形を作る。
3. 粗い解像度から細かい解像度まで、複数のスケールで処理する。
4. 各スケールで、地形の傾きから力場を作る。
5. 力場に沿って粒子を運ぶ。
6. 粒子が通った場所の高さ、摩耗、堆積、流量を更新する。
7. 最後に補助フィールドを整えて出力する。

ここで重要なのは、単に「下り坂を削る」だけではないことです。
KTT は粒子を動かしながら、削った場所を `wear`、堆積した場所を `deposits`、流れの通過量を `flows` として持ち続けます。
そのため、前の反復でできた水路が次の反復の流れに影響し、筋が少しずつ育ちます。

## 1. 入力地形を整える

最初に、入力された Heightfield を作業用の地形として扱います。

HDA には `Source Terrain Detail Smoothing` という考え方があります。
これは、地形に細かすぎるノイズがあると水の流れが散らばりすぎるため、シミュレーション前に少しだけ地形をならす処理です。

ただし、ならしすぎると山らしい粗さが消えます。
そのため KTT には後段で細部を戻す `Add_Detail_Pass` があります。

つまり考え方はこうです。

1. 水の流れを計算しやすいように、一度地形を少しきれいにする。
2. 侵食後に、元地形の細かい質感を必要な場所へ戻す。

## 2. マルチグリッドで大きい谷から作る

KTT は、いきなり最終解像度だけで侵食しません。
粗い解像度と細かい解像度を組み合わせます。

粗い解像度では、大きな谷や地形全体の流れを作ります。
細かい解像度では、支流や浅いリルのような細部を作ります。

この考え方がないと、次のような問題が起きます。

- 細かい筋だけが大量に出て、大きな谷の骨格が出ない。
- 逆に、大きい面が滑ったように削れて、山らしい稜線が消える。
- 解像度ごとの粒子移動距離が合わず、四角いブロック状の跡が出る。

KTT の `Feature Size`、`Reference Detail Size`、`Use Multigrid Acceleration` は、このスケール管理に関係します。

## 3. 力場を作る

水を動かすには、まず「どちらへ流れそうか」を計算します。
KTT では `Update_Forces` という処理で、各セルに `fx` と `fy` のような力を作ります。

基本は高さの勾配です。
周囲 3 x 3 の高さを見て、中心より高いか低いかを調べます。
水は高い方から低い方へ流れるので、勾配の逆向きが流れ方向になります。

ただし KTT はここで、ただの高さだけを見ません。
`wear` という「すでに削られた跡」も力場に戻します。

この戻し具合が `Flow Volume` です。

`Flow Volume` が効くと、前の反復で少し削られた筋に次の水が集まりやすくなります。
これが、細い水路が育つためにとても重要です。

## 4. 粒子をばらまく

次に、地形上へたくさんの粒子を置きます。
この粒子は水滴や土砂そのものというより、「水がここを通った」という処理単位です。

KTT では、反復ごとに粒子の開始位置を少し変えます。
毎回同じ場所から始めると人工的な模様になるためです。

粒子を置くかどうかには、いくつか条件があります。

- 斜面が十分にあるか。
- 尾根のような凸部分で、削れ始める理由があるか。
- `Erosion Granularity` による間引きを通過したか。
- すでに同じ反復で処理済みの場所ではないか。

`Erosion Granularity` は少し直感と違います。
実装時は、どのくらい粒子を間引くかとして扱うのが理解しやすいです。

## 5. 粒子を流す

粒子は、力場に沿って少しずつ移動します。

移動には速度があります。
速度は次の要素で変わります。

- 力場が強いほど加速する。
- `Friction` が大きいほど減速する。
- `Sediment Velocity` が大きいほど移動しやすい。
- 急な斜面では、自動的に移動量が抑えられる。

粒子は `Channel Length` に応じた距離だけ進みます。
細かい解像度では、同じ距離を表現するためにステップ数が増えます。

## 6. 削るかどうかを判定する

粒子が移動するたび、その場所を削るかどうかを判定します。

主に使うのは角度です。

- `Wear Angle`: これ以上なら削れ始める。
- `Deposit Angle`: これ未満なら堆積側になりやすい。
- `Max Erosion Angle`: これ以上の急斜面では削りを止める。

内部では角度をそのまま比較せず、`tan(angle)` に変換して勾配と比較します。
これは、地形の傾きが rise/run の比として扱われるためです。

この判定が弱すぎると、斜面全体が滑り落ちたように削れます。
逆に強すぎると、水路がほとんどできません。

## 7. 高さを更新する

KTT の中心的な高さ更新は、かなりシンプルです。

粒子の現在位置を `h1` とします。
粒子の進行方向の前を `h2`、後ろを `h3` とします。

そして、現在の高さを前後平均へ少し近づけます。

```text
new_height = lerp(h1, (h2 + h3) / 2, Erosion Strength)
```

これは、土砂容量を計算するタイプの侵食とは違います。
水路方向に沿って地形をならすことで、流れた跡を作る考え方です。

ただし、この処理をそのまま強くかけると、山の斜面全体が布のように滑った見た目になります。
そのため、実装側では流れが収束している場所や、何度も粒子が通った場所を優先して削る調整が必要になります。

## 8. Channeling で水路を強調する

`Channeling` は、単純に削りを強くするパラメータではありません。
KTT の実装では、主に「高さが増えた分を打ち消す」方向に働きます。

つまり、粒子処理で堆積して盛り上がったぶんを、`Channeling` の割合でキャンセルします。

これにより、水路の中に土砂が戻りすぎず、細い溝が残りやすくなります。

## 9. carry で土砂のつじつまを合わせる

粒子が削ったり堆積したりすると、場合によっては土砂が無から増えたような状態になります。
KTT では `carry` のような値で、粒子が持っている土砂量のつじつまを合わせます。

考え方は単純です。

- 削ったら粒子が土砂を持つ。
- 堆積したら粒子の土砂が減る。
- 持っていない土砂を堆積しそうになったら、高さを戻す。

これにより、谷底や緩斜面に堆積が出ても、破綻しにくくなります。

## 10. 補助フィールドを蓄積する

KTT は、高さだけでなく補助フィールドも作ります。

主なものは次の通りです。

| フィールド | 意味 |
| --- | --- |
| `deposits` | 堆積した量 |
| `flows` | 粒子や水が通った強さ |
| `age` | 侵食による古さ、摩耗感 |
| `wear` | 削られた跡 |

これらは見た目の調整にも、次の反復にも使えます。
特に `wear` を力場へ戻すと、水路が自己強化されます。

## 11. 細部を戻す

シミュレーション前に地形をならすと、流れはきれいになります。
しかし、そのままだと山の質感も消えます。

そこで KTT には `Add_Detail_Pass` があります。

これは、元の地形が持っていた細かい凹凸を、侵食後の地形へ戻す考え方です。
ただし、水路の中へ完全に戻すと谷筋が埋まってしまうため、侵食された場所では弱め、未侵食の尾根や斜面では強めに戻します。

この処理があると、山らしい粗さと、水で削られた滑らかな流路を両立しやすくなります。

## 12. 出力を整える

最後に、高さと補助フィールドを出力します。

Terrain Editor では主に次を扱います。

- `Heightmap`: 侵食後の高さ。
- `Deposits`: 堆積量。
- `Flows`: 流れの通過量。

`Flows` を見ると、どこに水が集まっているかがわかります。
`Deposits` を見ると、削られた土砂がどこに残っているかがわかります。

## パラメータを直感で見る

| パラメータ | 直感的な役割 |
| --- | --- |
| `Feature Size` | どのくらい大きな地形特徴を扱うか |
| `Geological Age` | どれくらい長く侵食されたか |
| `Simulation Iterations` | シミュレーションを何回回すか |
| `Channel Length` | 粒子がどれくらい長く流れるか |
| `Erosion Strength` | 1ステップごとの削りの強さ |
| `Channeling` | 水路を埋め戻しにくくする強さ |
| `Friction` | 流れの勢いをどれくらい減衰させるか |
| `Wear Angle` | 削れ始める斜面の条件 |
| `Max Erosion Angle` | 急すぎる斜面を削りすぎないための上限 |
| `Erosion Granularity` | 粒子密度、筋の出方 |
| `Flow Volume` | 既存の削れ跡へ水を集める強さ |
| `Small Channel Influence` | 細いリルをどれくらい出すか |
| `Reference Detail Size` | スケール依存計算の基準 |
| `Source Terrain Detail Smoothing` | 流れ計算前に入力地形をどれくらいならすか |

## 見た目が崩れるときの考え方

### 斜面全体が滑る

削りが谷筋ではなく面に入っています。

見るべき点:

- `Erosion Strength` が強すぎないか。
- `Max Erosion Angle` が広すぎないか。
- 流れの収束や `flows` に寄せた重み付けがあるか。
- 細部パスが強すぎないか。

### 山らしさが消える

入力地形の大きな起伏や高周波ディテールが平均化されています。

見るべき点:

- `Source Terrain Detail Smoothing` が強すぎないか。
- `Add_Detail_Pass` 相当で元地形の細部を戻しているか。
- Fluvial Erosion の前に山らしい ridged/fractal な地形が入っているか。

### 細い筋だけが出る

大きい谷の骨格が足りません。

見るべき点:

- マルチグリッドの粗いレベルが効いているか。
- `Feature Size` が小さすぎないか。
- `Channel Length` が短すぎないか。

## Terrain Editor で再現するときの優先順位

KTT らしさへ近づけるなら、次の順に確認するとわかりやすいです。

1. 入力地形が山らしいか。
2. 粗いスケールで大きな谷が作れているか。
3. 力場に `wear` が戻って、水路が自己強化されているか。
4. 粒子が斜面全体ではなく、流れが集まる場所を削っているか。
5. `deposits` と `flows` が補助出力として確認できるか。
6. 最後に元地形の細かいディテールを戻しているか。

この順番で見ると、単なる平滑化なのか、水路形成なのか、山の素材不足なのかを切り分けやすくなります。
