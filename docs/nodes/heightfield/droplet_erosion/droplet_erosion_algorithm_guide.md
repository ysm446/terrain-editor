# Droplet Erosion アルゴリズム入門

このメモは、`Droplet Erosion` ノードが何をしているのかを、実装の細部へ入る前に
段階的に理解するための読み物です。パラメータ一覧と入出力は同フォルダの
[droplet_erosion_node.md](droplet_erosion_node.md) にまとめています。
実装は [`src/evaluation/DropletErosion.cpp`](../../../../src/evaluation/DropletErosion.cpp) と
共有ヘルパ [`src/evaluation/ParticleErosionCommon.h`](../../../../src/evaluation/ParticleErosionCommon.h) です。

## まず何をするノードか

`Droplet Erosion` は、地形をゼロから作るノードではありません。
入力されたハイトフィールドの上に、雨粒が斜面を流れ下りながら土を削り、
谷底や緩斜面へ土砂を置いていった跡を加えるノードです。

考え方は「**水滴 (droplet) を 1 粒ずつ斜面に落として転がす**」という、
業界標準の粒子ベース水力浸食 (Sebastian Lague / Hans Theobald Beyer 系) です。
Multi-Scale Erosion が「全セル同時に解析的に解く」のとは対照的に、こちらは
「個々の水滴の軌跡を追う」ラグランジュ的なアプローチです。

1 粒の水滴は次の状態を持って斜面を流れます。

| 状態 | 意味 |
| --- | --- |
| `position` | 連続座標での現在位置 (セル間も取れる) |
| `direction` | 進行方向 (慣性で前方向を引きずる) |
| `speed` | 速度。下り坂で加速する |
| `water` | 水量。蒸発で少しずつ減る |
| `sediment` | いま運んでいる土砂の量 |

## 全体の流れ

おおまかな順番は次の通りです。

1. 入力ハイトフィールドを受け取る。
2. (Multigrid 有効時) 粗い解像度から目標解像度まで、段階的にピラミッドを上る。
3. 各レベルで、`Droplet Density`(1 セルあたりの水滴数)× セル数 個の水滴を 1 粒ずつ流す。
   - 各水滴は `Travel Distance (m)` 分の距離だけ流れる。1 ステップで約 1 セル(= `cellSize` メートル)進むので、ステップ数 = `Travel Distance / cellSize`。
   - ステップごとに「削る / 運ぶ / 置く」を判断して地形を直接書き換える。
4. 流量 (`flows`) を log 圧縮して正規化し、最終解像度の高さを出力する。

水滴ループは高さを直接書き換えながら進むため逐次実行です (= 決定論的)。
水滴の散布位置は `Seed` から作った疑似乱数で地形全体へ均等にばらまきます。

## 1 ステップで起きること

水滴の 1 ステップは次の手順です。コード上は
[`RunDropletLevel`](../../../../src/evaluation/DropletErosion.cpp) の内側ループに対応します。

### 1. 進む方向を決める (慣性 + 勾配)

```text
dir = dir × inertia - gradient × (1 - inertia)
```

- `inertia = 0` なら、その場の勾配 (最急降下方向) に正確に従う。
- `inertia` が大きいほど、直前の進行方向を保ったまま流れる。

慣性があると、水滴は谷壁に当たっても一気に向きを変えず、ゆるやかに曲がって
蛇行や慣性で掘られた外岸が出やすくなります。方向を正規化して 1 セル分進みます。
進んだ先がグリッド端に出たら、その水滴は終了します。

### 2. 高さ差と運搬容量を計算する

進んだ先と現在地の高さ差 `dH = newHeight - height` を見ます (下りなら負)。

```text
slope    = -dH / cellSize                       (rise/run。真の勾配)
capacity = max(slope, minSlope) × speed × water × sedimentCapacity
```

`capacity` は「この水滴がいま運べる土砂の上限」です。

- 急斜面ほど (slope 大)、速いほど (speed 大)、水が多いほど (water 大) たくさん運べる。
- `Min Slope` は、ほぼ平坦な場所でも容量を 0 にしないための下限。これが無いと
  平地で容量が 0 になり、運んできた土砂を全部その場に落としてしまう。

> 重要な点として、`slope` は「セル 1 個分の高さ差」ではなく `dH / cellSize` で
> **真の勾配 (rise/run)** に正規化しています。これを省くと、粗いピラミッドレベル
> (cellSize が大きい) ほど同じ地形で容量・浸食が数倍効いてしまい、解像度を変える
> たびに結果がドリフトします。

### 3. 削る / 運ぶ / 置くを判断する

高さ差と、いま運んでいる土砂 `sediment` と `capacity` の関係で 3 通りに分岐します。

| 状況 | 条件 | 動作 |
| --- | --- | --- |
| 登り坂に入った | `dH > 0` | 窪地を埋める。`min(dH, sediment)` だけ**現在地に**堆積し、水滴が乗り越えられるようにする |
| 過飽和 | `sediment > capacity` | 余った土砂 `(sediment - capacity) × Deposition Strength` を**放射ブラシで**堆積する |
| 余裕あり | それ以外 | `min((capacity - sediment) × Erosion Strength, -dH)` を**放射ブラシで**削り、土砂に加える |

ポイント:

- **登り坂の窪地埋めだけは単セル** (`SplatBilinear`) です。埋めるべきは窪地そのもの
  なので、周囲に広げてはいけません。
- **削りと過飽和堆積は放射ブラシ** (`ApplyBrush`、`Erosion Radius` セル) で広げます。
  単セルに削り・堆積を集中させると、特に粗いレベルをアップサンプルしたときに
  1 セルの穴や丸い瘤 (pimple) になります。半径方向に重み付けして撒くことで、
  滑らかな谷壁・土手になります。
- 削り量は `-dH` でクランプします。1 ステップで進行先より深く掘って逆勾配を
  作らないためです。

### 4. 速度・水量を更新する

```text
speed = sqrt( max(0, speed² + (-dH) × gravity) )       (下りで加速、登りで減速)
water = water × (1 - evaporation)^cellSize             (進んだ距離だけ蒸発)
```

`water` が `1e-4` を下回ったら、その水滴は寿命を終えます。容量は水量に比例するので、
**蒸発が速いと末端で容量が急減し、谷の終端に土砂がまとめて落ちます**。
`Evaporation` は「1 メートル進むごとの損失」で、セルサイズ分だけ複利圧縮します
(`(1 - evaporation)^cellSize`)。こうすると細かいグリッドでステップ数が増えても
1 メートルあたりの蒸発量は一定になり、到達距離が解像度で変わりません。既定が
小さめ (0.002 /m) なのは、水滴を尾根から谷底まで届かせて水路が中腹で途切れない
ようにするためです。同じ理由で `Travel Distance (m)` も 512 m と長めです。

最後に位置を進んだ先へ移し、次のステップへ進みます。

## 流量 (Flows) の集積

各ステップで通過したセルに `water` を加算したものが `flows` です。
水滴が何度も通る谷ほど大きな値になり、樹枝状のドレナージ網が浮かび上がります。

集積値は長い裾を持つので、最後に `log(1 + flow)` で圧縮してから [0,1] 正規化します
([`FinalizeLevel`](../../../../src/evaluation/ParticleErosionCommon.h))。
これで細い支流から本流まで一枚のマスクで見やすくなります。

## マルチグリッド — 大局から細部へ

`Use Multigrid` を有効にすると、粗い解像度 (`kCoarsestPyramidLevel = 64`) から
目標解像度まで段階的に処理します。

```text
levels  = [64, 128, 256, ..., target]
heights = downsample(input, 64)
for each level:
    if not first: heights = upsample(heights, level)
    水滴を流す (粒子数は面積比でスケール)
```

なぜ効くのか:

- 粗いレベルではセル数が少なく、少ない水滴で地形全体に大きな谷ネットワークが
  早く決まる。
- 細かいレベルでは大局構造がすでに決まっているので、**細部の刻み込みだけ**が仕事になる。
- 各レベルの粒子数は [`ParticlesForLevel`](../../../../src/evaluation/ParticleErosionCommon.h)
  が面積比でスケールするので、粒子密度 (セルあたりの水滴数) がほぼ一定に保たれ、
  粗いレベルが安く済む。`Droplet Density` 自体が「1 セルあたり」の指定なので、
  目標解像度を変えても全レベルで密度が一定になります。

Multi-Scale Erosion と同じ「粗→細ピラミッド」の思想です。

## Fluvial Erosion との違い

姉妹ノード `Fluvial Erosion` (KTT 風、
[../fluvial_erosion/fluvial_erosion_node.md](../fluvial_erosion/fluvial_erosion_node.md)) との違いです。

| 観点 | Droplet Erosion | Fluvial Erosion (KTT 風) |
| --- | --- | --- |
| 削る基準 | 運搬容量 (容量 - 現保有量) で削る/置くを切り替え | 実効勾配に比例して stream power 方式で削る |
| 土砂の扱い | 1 水滴が容量まで持ち、過飽和で落とす | 削った分を運び、`Deposit Angle` 未満で落とす |
| 実行 | 1 水滴ずつ逐次 (決定論的) | 反復ごとに全粒子をスナップショットへ並列トレース |
| バックエンド | CPU のみ | CPU / GPU (D3D12 compute) |
| 解像度一貫性 | 寿命・蒸発・半径・密度すべてメートル/セル密度基準 | 同左 (`Channel Length` など物理量基準) |
| 得意な見た目 | 慣性のある蛇行、谷底の堆積、扱いやすい既定値 | 自己強化する樹枝状水路、尾根→谷底の連続した刻み |

どちらも `Heightmap` 入力から `Heightmap` / `Flows` / `Deposits` を出力し、出力ピンを
クリックするとプレビューの可視化チャンネルが切り替わります。

## 見た目が崩れるときの考え方

### 水路が中腹で途切れる、谷底まで届かない

水滴が途中で寿命を終えています。

- `Travel Distance (m)` を増やす (既定 512 m。短いと到達距離が足りず途中で消滅する)。
- `Evaporation` を下げる (大きいと容量 ∝ 水量のため末端で失速して止まる)。
- `Min Slope` が小さすぎると緩斜面で容量が枯れて運搬が止まることがある。

### 谷底や扇状地が丸い瘤・点状の穴になる

削り・堆積が単セルに集中しています。

- `Erosion Radius (m)` を上げて放射ブラシを広げる (内部でセル数に換算し 0.5〜16 セルでクランプ)。
- Multigrid 有効時は粗いレベルの単セル変化がアップサンプルで目立つので、まず
  `Erosion Radius (m)` を見直す。

### 削れすぎる / ほとんど削れない

- 全体の削れ量は `Erosion Strength` で調整。
- それでも足りない/効きすぎる場合は `Sediment Capacity` (運べる量の基準) を動かす。
  容量が大きいほど水滴がたくさん削って下流へ運ぶ。
- `Gravity` を上げると下りで加速して運搬量が増え、谷が深くなる。

### 解像度を変えると結果が変わる

解像度に影響するパラメータはすべて物理量 (メートル / セル密度) 基準にしてあるので、
原則として `Simulation Resolution` を変えても結果はほぼ一貫します。

- `Travel Distance (m)` (到達距離) と `Evaporation (/m)` (1 m あたりの蒸発) はメートル基準で、
  セルサイズ分だけステップ換算・複利圧縮されます。
- `Erosion Radius (m)` (ブラシ半径) もメートル基準で、内部でセル数に換算されます。
- `Droplet Density` は 1 セルあたりの水滴数なので、解像度が変わっても密度が一定です。
- 容量の勾配項 (`slope = -dH / cellSize`) と速度更新は元から解像度不変です。
- `Use Multigrid` を有効にすると大局構造が粗いレベルで先に確定し、さらに安定します。

それでも細部 (粒子由来の微細なノイズや、極端に高い解像度でのブラシ上限クランプ) は
解像度で多少変わります。気になる場合は仕上げの `Heightmap Blur` で吸収できます。

## チューニングの優先順位

新規にノードを置いたとき、迷ったら次の順で試します。

1. **`Droplet Density`** を上げて密度を確保する (少ないとまばらで荒い)。
2. **`Travel Distance (m)` / `Evaporation (/m)`** で水滴が谷底まで届くか確認する。
3. **`Erosion Strength`** で全体の削れ量を合わせる。
4. **`Erosion Radius (m)`** で谷壁・堆積の滑らかさを調整する。
5. 必要なら **`Inertia`** を上げて蛇行を、**`Sediment Capacity` / `Gravity`** で
   運搬・堆積のバランスを調整する。

仕上げには下流に **`Heightmap Blur`** を軽くかけると、粒子由来の細かいノイズが
取れてさらに自然に見えます。
