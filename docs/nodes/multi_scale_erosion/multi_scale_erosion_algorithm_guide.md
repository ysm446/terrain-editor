# Multi-Scale Erosion アルゴリズム入門

このメモは、`Multi-Scale Erosion` ノードが何をしているのかを、実装の細部へ入る前に段階的に理解するための読み物です。
正確なシェーダー対応や数式は `multi_scale_erosion_node.md` にまとめています。

## まず何をするノードか

`Multi-Scale Erosion` は、地形をゼロから作るノードではありません。
入力されたハイトフィールドに対して、樹枝状の谷ネットワーク、急斜面の崩落、谷底の土砂堆積を加えるノードです。

KTT との大きな違いは「**水を粒子で動かさず、グリッド全体で一度に解析的に解く**」ことです。
KTT が「水滴を流して通った跡を削る」のに対し、Multi-Scale Erosion は「各セルに上流から流れてくる水量を計算で求めて、その量に応じて削る」と考えます。

考え方は次の 3 つの組み合わせです。

1. 水の量と勾配から、どこをどれだけ削るか決める (SPE: 河川浸食)。
2. 急すぎる斜面を、隣のセルへ少しずつならす (Thermal: タラス崩壊)。
3. 運ばれてきた土砂を、流れが弱まった場所に置いていく (Deposition: 土砂堆積)。

この 3 つを 1 反復として、何度も繰り返します。

## 全体の流れ

おおまかな順番は次の通りです。

1. 入力ハイトフィールドを受け取る。
2. (Multigrid 有効時) 粗い解像度から目標解像度まで、段階的にピラミッドを上る。
3. 各レベルで、`Iterations` 回だけ次を繰り返す:
   1. SPE で削る。
   2. Thermal でならす。
   3. Deposition で土砂を堆積させる。
4. 最後の解像度で完成した高さを出力する。

KTT が「粒子をばらまいて流す」のに対し、こちらは「全セル同時に各パスを実行する」イメージです。
そのため、CPU でもマルチコアで並列化しやすく、GPU でもそのまま走らせやすい構造になっています。

## 1. SPE — 水の量と勾配から削る

SPE (Stream Power Erosion) は、地形学の古典的な河川浸食モデルです。
基本式は次の形をしています。

```text
削り量 = k × 流量^m × 勾配^n
```

| 記号 | 意味 |
| --- | --- |
| `k` | 削れやすさ。`SPE Strength` |
| 流量 | 上流から集まってきた水の量。`stream` |
| 勾配 | その場の最大の傾き |
| `m`, `n` | 効き方の冪。`Stream Exponent` / `Slope Exponent` |

直感は次の通りです。

- 上流から集まる水が多いほど削れる (= 集水域が広い大きな川ほど深く削る)。
- 急斜面ほど削れる (= 流速が速くなって削る力が強くなる)。
- どちらかが 0 なら削れない (= 谷頭や平地は削れない)。

これが、樹枝状の谷ネットワークが自然に出てくる理由です。
上流の小さな谷は流量が少ないので浅く、下流に行くほど合流して深くなります。

## 2. 流量 (stream) はどう計算するか

「上流から集まってくる水の量」は、各セルが下流の隣接セルへどれだけ流れるかという重みから計算します。

仕組みはこうです。

1. 各セルから 8 方向の隣接セルを見て、下り勾配だけを抽出する。
2. 勾配の大きさを `flow_p` 乗して重みにする (`Flow Exponent`)。
3. 全方向の重みを足して 1 にして、出力割合を決める。
4. 「私 (セル q) からあなた (セル p) への割合」を q から p への流入として加算する。

この計算は、毎反復ごとに地形が更新されるたびに繰り返します。
そのため、最初の何反復かで `stream` がだんだん大きくなり、どこかで安定します (steady state)。

`Flow Exponent` を大きくすると、最も急な方向に集中して流れる傾向が強まります。
`Flow Exponent` を小さくすると、複数方向に分散して流れる傾向が強まります。

## 3. Thermal — 急斜面を崩す

水だけでは、削った後にナイフのように鋭い V 字溝が残ります。
実際の地形は、急すぎる斜面が重力で崩れて落ち着きます (= タラス崩壊、安息角)。

Thermal はこれを再現するパスです。
仕組みはシンプルです。

1. 各セルの周囲 3×3 の隣接セルを見る。
2. 隣接セルとの勾配が `Threshold Angle` を超えていたら、土砂を移動する。
3. 高い側からは出ていく (`distributeMul`)、低い側へは入ってくる (`receiveMul`)。
4. 純移動量だけ、自分の高さを増減させる。

`Threshold Angle` (安息角) は、岩や土が安定して保持できる最大の勾配です。
30°前後がデフォルトで、岩石は急めに、土は緩めに崩れます。

`Noisify Angle` を有効にすると、空間的に少しゆらぎを加えて、岩質の不均一を表現できます。

このパスがあるおかげで、SPE の鋭い V 字が U 字寄りに丸まり、稜線や谷壁が自然な姿になります。

## 4. Deposition — 土砂を運んで置く

水は土砂を運びますが、流れが弱まった場所では運びきれず、底に置いていきます。
これが堆積 (deposition) です。

仕組みはこうです。

1. 各セルが「運ぶ余力」(`streamPower`) を計算する。これは流量と勾配から決まる。
2. 上流からの土砂 (`sed`) を受け取る。
3. もし `運んでいる土砂量 > 運ぶ余力` なら、超過分の 10% を堆積させる。
4. 残った土砂は下流へ流す。
5. 局所最小 (pit、=湖や盆地) では、土砂が出口を持たないので貯まる。

数式的には次のような条件です。

```text
if deposition_strength × sed > streamPower:
    deposit = (deposition_strength × sed - streamPower) × 0.1
    height += deposit
    sed -= deposit
```

`Deposition Strength` を上げると堆積が起きやすくなり、谷底が早く埋まります。
`Rain` は単位セルあたりに降る雨量で、流量の基準値を決めます。

## 5. SPE → Thermal → Deposition の順序

順序には意味があります。

1. **SPE** で水流による侵食をかける (V 字溝ができる)。
2. **Thermal** で急斜面をならす (V 字が U 字に近づく)。
3. **Deposition** で運んできた土砂を置く (谷底に積もる)。

この 3 つを 1 セットとして、`Iterations` 回繰り返します。
1 回ごとの変化は小さく、何回も重ねることで自然な地形に近づきます。

順序を入れ替えるとどうなるか:

- Thermal が最初だと、削る前に地形が均されて流路ができにくい。
- Deposition が最初だと、まだ土砂が無い状態で計算するので意味が薄い。
- SPE → Deposition → Thermal の順だと、堆積後にならされて堆積感が薄れる。

論文の推奨順 (SPE → Thermal → Deposition) が経験的にバランスが良いです。

## 6. マルチグリッド — 大局から細部へ

`Use Multigrid` を有効にすると、粗い解像度から目標解像度まで段階的に処理します。

```text
levels = [64, 128, 256, ..., target]
heights = downsample(input, levels[0])
for each level:
    if level is not the first: heights = upsample(heights, level)
    Iterations 回反復 (SPE / Thermal / Deposition)
```

なぜこれが効くのか:

- 粗い解像度ではセル数が少なく、`stream` が少ない反復で全体に伝播する。
- そのため、大きな谷ネットワークの**位置と本数**が早く確定する。
- 細かい解像度では、すでに大局構造が決まっているので、**細部の追加だけ**が仕事になる。

これがないと、目標解像度だけで反復することになり、

- `stream` の伝播が反復数を消費する (path_length / cellSize 回必要)。
- 解像度を変えると `stream` の発達度が変わって、見た目が大きくドリフトする。

論文の "Multi-Scale" は、この粗→細ピラミッドのことを指しています。

## 7. 解像度を変えても結果が変わらない仕組み

シェーダー原典では `matter = eps × cellArea` のように `cellSize²` に比例する係数を使っています。
これだと解像度を倍にすると Thermal の効きが 1/4 になってしまい、同じパラメータで結果が大きく変わります。

Terrain Editor では:

- `Thermal` の `matter` を **基準 cellSize 4m** での `cellArea = 16` で固定する。
- `Deposition` の `rain × cellArea` も同じ基準で固定する。

これで反復あたりの効きが解像度に依存しなくなります。
基準 4m (= 解像度 512 / 2048m terrain) でチューニングした値はそのまま使え、他の解像度でも近い結果になります。

ただし `stream` 累積は前進反復なので、完全な解像度不変は構造的に不可能です。
解像度を上げる場合は `Iterations` を比例的に増やすのが推奨です (例: 512 → 1024 で 50 → 80〜100)。
Multigrid 有効時はピラミッドの粗い段階で `stream` がほぼ確定するので、この問題はほぼ気になりません。

## 8. KTT との違い

| 観点 | KTT | Multi-Scale Erosion |
| --- | --- | --- |
| 離散化 | ラグランジュ (粒子輸送) | オイラー (グリッド全体で同時) |
| 流量 | 粒子の通過数 | 解析的な D8 重み付き累積 |
| 並列性 | 粒子間の重複処理に注意必要 | セル独立で並列化簡単 |
| 出やすい谷 | 蛇行・編組流路、谷底のディテール | 樹枝状ネットワーク、稜線シャープ化 |
| 完全な解像度不変 | 部分的に補正済み | 部分的に補正済み |
| GPU 親和性 | 中程度 | 高い |

両者は補完関係にあります。
KTT は谷底の細部や蛇行のリアルさが得意で、Multi-Scale Erosion は大局のネットワーク構造とリッジシャープ化が得意です。

## 9. 出力ピン

| ピン | 内容 |
| --- | --- |
| `Heightmap` | 浸食後の高さ |
| `Flows` | 流量累積 (D8 重み付き)。樹枝状ネットワークが見える |
| `Deposits` | 堆積した土砂量。湖底や扇状地が見える |

プレビューは出力ピンをクリックすると切り替わります。
`Flows` を見ると水がどう集まっているか、`Deposits` を見るとどこに土砂が残っているかがわかります。

## パラメータを直感で見る

### 反復制御

| パラメータ | 直感的な役割 |
| --- | --- |
| `Iterations` | 各レベルで何回繰り返すか。多いほど成熟する |
| `Use Multigrid` | 粗→細のピラミッド処理を使うか |
| `Enable Stream Power` | SPE パスの ON/OFF |
| `Enable Thermal` | Thermal パスの ON/OFF |
| `Enable Deposition` | Deposition パスの ON/OFF |

### SPE (河川浸食)

| パラメータ | 直感的な役割 |
| --- | --- |
| `SPE Strength` | 削りの強さ。1 反復あたりの削れ量 |
| `Stream Exponent` | 流量の効き具合。大きいほど大河の優位が強くなる |
| `Slope Exponent` | 勾配の効き具合。大きいほど V 字が深くなる |
| `Max Stream Power` | 削り量の上限。暴走防止 |
| `Flow Exponent` | 流量分配の集中度。大きいほど最急方向に集まる |
| `Time Step` | 1 反復あたりの時間刻み |

### Thermal (タラス崩壊)

| パラメータ | 直感的な役割 |
| --- | --- |
| `Threshold Angle` | これを超える勾配は崩れる。安息角 |
| `Thermal Strength` | 1 反復あたりの再配分量 |
| `Noisify Angle` | 安息角を空間ノイズで揺らす |
| `Noise Min/Max` | 角度の揺らぎ範囲 |
| `Noise Wavelength` | 角度ノイズの空間スケール |

### Deposition (堆積)

| パラメータ | 直感的な役割 |
| --- | --- |
| `Deposition Strength` | 堆積率。大きいほど早く土砂が落ちる |
| `Rain` | 単位セルあたりの雨量 |

## 見た目が崩れるときの考え方

### V 字溝が鋭すぎる、シダの葉のような対称パターンが出る

SPE が強すぎ、Thermal が弱すぎです。

見るべき点:

- `Slope Exponent` を 2.0 → 1.2〜1.5 に下げる (最も効く)。
- `Thermal Strength` を上げる (シェーダー既定の 0.00005 は弱すぎる。`0.0005` 以上が目安)。
- `Threshold Angle` を 30° → 20〜25° に下げる。
- 入力地形に多少の不規則性があるか確認する。均質すぎると対称パターンが出やすい。

### 谷ネットワークが薄っぺらい、本流しかない

`Flow Exponent` が大きすぎて流量が一極集中しています。

見るべき点:

- `Flow Exponent` を 1.3 → 1.0 に下げる。
- `Iterations` が足りていない可能性 (支流が育つ前に止まっている)。
- Multigrid が無効だと、解像度に対して反復が足りなくなりやすい。

### 反復するごとにどんどん上に伸びる、針状のスパイクが出る

(これは過去の修正で解決済みですが) Deposition の pit 判定が逆向きの場合に起きる症状です。
コミット履歴で `Fix deposition pit logic` を経由していれば直っているはずです。

### 反復すると地形が低くなりすぎる

SPE が削りすぎ、Multigrid との組み合わせで効果が積算されています。

見るべき点:

- Multigrid 有効時は `Iterations` の意味が「各レベルでの反復数」になる。総反復数は概ね 4 倍。`30` 程度から始める。
- `SPE Strength` を 0.0005 → 0.0002 に下げる。
- 数百反復に達すると元地形がほぼ平坦に向かうのは構造上の性質 (= 浸食収束)。それ以上反復しないこと。

### 解像度を変えると結果が大きく変わる

`Use Multigrid` を有効にすると大幅に改善します。
それでも残る場合は:

- `Iterations` を解像度に比例して増やす (`stream` 累積が前進反復で時間がかかる)。
- 入力解像度を `Heightmap Load` の `Simulation Resolution` で変えていないか確認 (これはハイトフィールド側の設定なので、解像度を上げると入力情報量も増える)。

## チューニングの優先順位

新規にノードを置いたとき、迷ったら次の順で試します。

1. **`Iterations`** を `30〜50` に。Multigrid 有効では各レベルで反復するので、これで十分な効果が出る。
2. **`Slope Exponent`** を `1.2〜1.5` に下げる。シェーダー既定の 2.0 は鋭すぎる。
3. **`Thermal Strength`** を `0.0005` 前後に上げる。既定の 0.00005 は実用上ほぼ効かない。
4. **`SPE Strength`** で全体の削れ量を調整。`0.0002` 前後から始めて、足りなければ上げる。
5. **`Threshold Angle`** で稜線の鋭さを調整。`20〜30°` の範囲。
6. 必要なら `Deposition` を OFF にして SPE + Thermal だけで形を作り、後から戻す。

仕上げには下流に **`Heightmap Blur`** (Radius `1.0〜1.5`、Strength `15〜25%`) を追加すると、SPE 由来の D8 階段アーティファクトが消えてさらに自然に見えます。

## Terrain Editor で再現するときの優先順位

Multi-Scale Erosion をうまく使うために、次の順に確認するとわかりやすいです。

1. 入力地形がノイズや既存の起伏を持っているか。完全に均質だと不自然な対称パターンが出る。
2. `Use Multigrid` が有効か。これがないと解像度依存と反復不足が両方起きやすい。
3. SPE で大局の谷ネットワークが見えているか (Flows ピンで確認)。
4. Thermal で V 字の鋭さが取れているか (3D プレビューで稜線をチェック)。
5. Deposition の効きが強すぎて谷底を埋めていないか。
6. 解像度を切り替えて大局構造が保たれているか (Multigrid のテスト)。

この順番で見ると、入力不足なのか、SPE が効きすぎなのか、Thermal が足りないのかを切り分けやすくなります。
